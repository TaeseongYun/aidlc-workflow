# backend-security-guard — vibe-coding security guard

AI-generated backend code is **fast but frequently vulnerable.** Empirical studies find
about 40% of Copilot-generated code contains security flaws, and AI-assisted commits leak
secrets roughly twice as often as human-only commits (6.4% vs 4.6% at the repo level).
On top of that, developers **overtrust** AI code, believing it to be safer than it is.
This skill fills that gap as a **review guard**. The rules here are **safety rules** and
must not be relaxed or weakened. Project `ctx/` overrides this document, but the security
floor is never lowered.

## Scope

- Targets: server source (Java/Kotlin/TS/JS/Python/Go, etc.), config (`application*.yml`, `.env`),
  Dockerfile — especially code that AI generated or was pasted in without review.
- What it does: **detect vulnerable patterns → propose safe alternatives** for each failure mode below.
- Delegate to adjacent skills: deep authN/authZ → [backend-auth], data exposure/encryption at rest →
  [backend-data-transactions], deep dependency/supply-chain → [backend-reliability].
- Mappings: OWASP Top 10 2021, OWASP API Security Top 10 2023, CWE Top 25.

## Core Rules — by AI-generated-code failure mode (must not be relaxed)

Each item: **rule → the failure AI commonly produces → red-flag**. Code examples in [reference.md](./reference.md).

### 1. Hardcoded secrets / config (CWE-798 · OWASP A05/A07)

- **Rule**: API keys · passwords · tokens · DB passwords come from **environment variables / secret manager**.
  Never in source · VCS · committed `.env` · Dockerfile. No default credentials.
- **Common AI failure**: `apiKey = "sk-..."`, `password = "admin"`, pasting example secrets verbatim,
  committing `.env`, Dockerfile `ENV SECRET=...`.
- **red-flag**: string-literal secrets, tracked `.env`, password inline in a connection string.

### 2. SQL / ORM injection (CWE-89 · OWASP A03)

- **Rule**: queries only via **parameterized / bound parameters**. Never concatenate user input into the
  query string. JPQL uses named parameters, native uses `?`/`:param`.
- **Common AI failure**: `"... WHERE name = '" + name + "'"`, interpolating values into JS template literals,
  taking sort/column names as input and concatenating them.
- **red-flag**: input joined into a query string with `+`/`${}`/`%s`, `Statement` (vs `PreparedStatement`).

### 3. Command / path-traversal / expression injection (CWE-78/22/94)

- **Rule**: no user input in OS commands — if unavoidable, use an argument array + allowlist. Normalize file
  paths and verify they stay inside the base directory. Never evaluate user input as code/template/expression.
- **Common AI failure**: `Runtime.exec("sh -c " + input)`, `new File(base + userPath)`,
  injecting input into `eval`/SpEL/templates.
- **red-flag**: input into `exec`/`ProcessBuilder("sh","-c",...)`, unvalidated `../` paths, `eval(`.

### 4. SSRF — server-side request forgery (CWE-918 · OWASP A10/API7:2023)

- **Rule**: when the server makes a request to a user-supplied URL, restrict it with a **host allowlist** and
  block internal/private IPs · the metadata endpoint (169.254.169.254) · localhost. Limit redirect following.
- **Common AI failure**: passing the input URL straight to `fetch`/`RestTemplate`/`HttpClient`.
- **red-flag**: a user URL handed to an HTTP client without validation.

### 5. Unsafe deserialization (CWE-502 · OWASP A08)

- **Rule**: never deserialize untrusted data into arbitrary types. JSON only into fixed DTOs. Forbid Java
  native serialization · `ObjectInputStream` · Jackson polymorphic `enableDefaultTyping` · unrestricted
  `SnakeYaml` loading.
- **Common AI failure**: `ObjectInputStream.readObject()`, `yaml.load(untrusted)`,
  enabling polymorphic typing.
- **red-flag**: untrusted bytes turned into objects, default typing, `pickle.loads`.

### 6. Broken access control — BOLA / BFLA (OWASP A01 · API1/API5:2023)

- **Rule**: on resource access, **re-verify ownership/permission on the server**. Do not allow access just
  because an `id` is present in the request (BOLA). Admin/function endpoints must check the role (BFLA).
  Details in [backend-auth].
- **Common AI failure**: only `repo.findById(pathId)` with no owner check. `/admin/*` handlers with no
  permission check.
- **red-flag**: fetching/updating directly by an id from the path/body, admin endpoints with no role check.

### 7. JWT / auth verification mistakes (CWE-347 · OWASP A07)

- **Rule**: JWT **signature verification is mandatory**, allowed-algorithm allowlist (block `alg=none` · `HS`↔`RS`
  confusion), verify `exp`/`iss`/`aud`. Passwords use bcrypt/argon2. Details in [backend-auth].
- **Common AI failure**: decode without verifying the signature, allow any `alg`, ignore expiry, password plaintext/MD5.
- **red-flag**: `decode` without verify, hardcoded symmetric key, no expiry check.

### 8. Weak crypto / randomness (CWE-327/338 · OWASP A02)

- **Rule**: password hashing is bcrypt/scrypt/argon2. Integrity/signing is SHA-256+. Symmetric is AES-GCM.
  Tokens · salts · IVs use **`SecureRandom`** (`Math.random`/`Random` forbidden). No home-rolled crypto.
- **Common AI failure**: `MD5(password)`, `SHA1`, AES **ECB**, fixed IV, `Math.random()` token.
- **red-flag**: `MessageDigest.getInstance("MD5")`, `"AES/ECB"`, `Math.random` for security.

### 9. Disabled security settings (OWASP A05)

- **Rule**: don't turn security features off just to "make it work" — `permitAll()` abuse,
  blanket CSRF off, changing `spring.jpa.ddl-auto` in production, defeating TLS certificate verification,
  cleartext, unauthenticated debug/actuator exposure.
- **Common AI failure**: `.anyRequest().permitAll()`, `TrustAllCerts`, `rejectUnauthorized:false`,
  `verify=False` (requests), actuator `*` exposure.
- **red-flag**: allow-everything security chain, certificate-verification bypass, open actuator/debug.

### 10. Excessive information disclosure / logging (OWASP A09 · CWE-209)

- **Rule**: never expose stack traces · SQL · internal paths to the client → [backend-api-contract].
  **Do not leave secrets · tokens · full PII in logs** → [backend-reliability].
- **red-flag**: exceptions in the response body, tokens/passwords logged.

### 11. Vulnerable / hallucinated dependencies — slopsquatting (OWASP A06 · LLM supply chain)

- **Rule**: verify an AI-suggested package **actually exists and is the legitimate package** (hallucination/slopsquatting).
  Pin versions · lockfile · SCA scan. Details in [backend-reliability].
- **Common AI failure**: installing a nonexistent or typo-similar package, pinning an old vulnerable version.
- **red-flag**: a package name you've never seen, an addition with no lockfile, a version with a known CVE.

## Vibe-guard review checklist

For backend code that AI generated or was pasted in quickly, before merge:

- [ ] No hardcoded keys · secrets · default credentials. No secrets in `.env`/Dockerfile.
- [ ] Every query uses parameter binding (no string concatenation).
- [ ] No unvalidated input in OS commands/file paths/expressions.
- [ ] User-URL fetch has an allowlist + blocks private/metadata IPs (SSRF).
- [ ] No untrusted deserialization (fixed DTOs only).
- [ ] Resource access re-verifies ownership/role (BOLA/BFLA).
- [ ] JWT signature · alg allowlist · exp verification. Passwords bcrypt/argon2.
- [ ] No weak hash (MD5/SHA1) · ECB · `Math.random` for security. `SecureRandom` used.
- [ ] Security settings not turned off (permitAll/CSRF/TLS verification/actuator).
- [ ] No stack traces · secrets exposed in responses/logs.
- [ ] Added dependencies are real · legitimate · version-pinned · CVE-free.
