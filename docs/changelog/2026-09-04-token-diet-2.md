# 2026-09-04: Token Diet 2 — Lazy Loading for Claude Code, Bookkeeping Script, Phase Files

## Background

A standard `/ctx-aidlc-run` session was estimated at ~2.5M tokens (~$4 on Claude Fable 5.1, ~$3 on Opus 5).
Three causes, none of them the workflow itself:

1. **The Claude Code entry point bulk-loaded 25 documents.** Claude Code runs `CLAUDE_COMMAND.md`
   (installed as `~/.claude/commands/ctx-aidlc-run.md`), not `SKILL.md`. Its "Required Reading Order"
   read ~30K tokens of core/common/templates at start regardless of depth level. The April lazy-loading
   change had only reached `SKILL.md`.
2. **Bookkeeping turns.** Every STEP start/complete/skip, GATE decision and user answer was a Read+Edit
   of `audit.md` and `aidlc-state.md` — 60~70 events per session, each one a turn that re-sends the whole
   context as cache reads.
3. **Whole documents loaded for one section.** `SKILL.md` (10.7K tokens) was loaded in full for every
   Phase; `stage-gate-rules.md` and `error-recovery.md` were read whole; brownfield STEP 1.5 explored
   the source tree by hand.

Also in this change: the `ctx-run` orchestrator skill was removed. Its unique hooks (technical-design
adherence, platform guidance, lazy-implementation ladder, Hallucination Guard Rule 0, build verification)
moved to `ctx-domain-exec` as "Pre-Implementation Loads"; docs now route implementation to
`/ctx-domain-exec` or an OMC/Ouroboros handoff.

## What changed (the STEP/GATE flow, artifacts, audit/state formats and invocation are unchanged)

### New helper scripts (`scripts/`)

| Script | Purpose |
|--------|---------|
| `aidlc-log.sh` | One call per event: appends the `templates/audit.md` block and updates `aidlc-state.md` checkboxes, Current Stage, Feature Status, Last Updated. Sub-commands `step`, `gate`, `answer`, `status`, `handoff`, `set`. Exit 2 when the docs are missing → manual fallback. |
| `md-section.sh` | Prints only the named section(s) of a markdown file (fence-aware). Used for `stage-gate-rules.md` (shared parts once, then one `### GATE-N:` section per gate) and `error-recovery.md` (resume procedure only). |
| `graph_inventory.py` | Drafts `component-inventory.md` from `graphify-out/graph.json` (PyPI `graphifyy` layout): packages, cross-package dependencies with EXTRACTED ratio, cycles, god nodes. Rows are marked `⚠️ UNCERTAIN (auto)` for STEP 1.5 to verify. Exit 3 when no graph → manual STEP 1.5. |

`tools/test-scripts.sh` runs their self-checks (fixture: `tools/fixtures/graph.sample.json`); CI runs it.

### `skills/ctx-aidlc-run/CLAUDE_COMMAND.md` (Claude Code)

- "Required Reading Order" (25 files) → BOOTSTRAP (3 workflow docs + project files) + the same PER-STEP
  LOADING table as `SKILL.md`. `README.md` of the workflow repo is no longer read.
- Real-time updates go through `aidlc-log.sh`; STEP 1.5 uses `graph_inventory.py` + `GRAPH_REPORT.md`
  sections when a graph exists. Everything else is verbatim.

### `skills/ctx-aidlc-run/SKILL.md` (Codex) + `phases/`

- STEP/GATE bodies moved unchanged into `phases/phase-a.md` (STEP 1 ~ GATE-1), `phase-b.md`
  (STEP 4 ~ GATE-3), `phase-c.md` (STEP 6.5 ~ GATE-5). `SKILL.md` keeps the common rules and a
  PHASE ROUTER that reads only the current Phase's file (matches the session-separation model).
- OUTPUT CONTRACT now points at `core/core-workflow.md` §8 (already loaded at BOOTSTRAP) instead of
  repeating the artifact list. STEP LIFECYCLE and the Real-time update rule are expressed as
  `aidlc-log.sh` calls.

### Validator / CI

- `tools/validate-skills.sh`: SCOPE-01 ignores a skill's references to its own directory; new REF-02
  (every `{{TEAM_AI_WORKFLOW_DIR}}/<path>` reference must exist) and TOKEN-01 (prompt-weight budget:
  `SKILL.md` ≤ 5,000, `CLAUDE_COMMAND.md` ≤ 4,000, `phases/*.md` ≤ 3,000 estimated tokens).
- `.github/workflows/validate.yml` runs `tools/test-scripts.sh`.

## Effect (estimates, char-based; standard depth, brownfield)

| Item | Before | After |
|------|-------:|------:|
| Claude Code start-up load | command 2.9K + docs ~30K | command ~3.7K + docs ~6K |
| `SKILL.md` prompt (Codex) | 10.7K | common ~4.6K + one Phase ≤ 2.6K |
| Bookkeeping turns per session | 60~70 | ~0 (script calls share the step's turn) |
| Brownfield STEP 1.5 input | 20~50K of source reads | inventory draft + report sections, 3~5K |
| Session total | ~2.5M | ~1.0M |

Exact numbers need `count_tokens` against the target model; see `tools/validate-skills.sh` TOKEN-01
for the heuristic used.

## Not changed

STEP order and conditions, GATE rules, artifact list and templates, audit/state formats, question
governance, session separation, `core/`, `common/`, `templates/` bodies, `ctx-aidlc-roadmap`.
